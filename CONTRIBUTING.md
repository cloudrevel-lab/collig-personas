# Contributing a persona

## 1. Create it in Collig

Use Collig's own distillation flow, not an external generator:

~~~text
/distill Ada Lovelace --for explain analytical engines in her voice
~~~

Review ~/.collig/personalities/ada-lovelace/PERSONALITY.md and edit it by hand
if the voice or facts need work.  The quality of the dossier matters more than
the number of sources.

## 2. Publish it

From a Collig checkout:

~~~bash
make push-personas personality=~/.collig/personalities/ada-lovelace
~~~

This validates your persona, runs the repository tests, regenerates
index.json, pushes a branch and opens a PR.

## 3. What reviewers check

- the dossier is recognisably that person, not a generic biography;
- quoted lines are accurate and attributed correctly;
- no private personal data, credentials or secrets;
- no executable files, symlinks or unexpected files;
- name/aliases are enough to discover the persona, and ambiguous names are
  distinguished by display_name/canonical_name;
- index.json is generated by make index, not edited by hand.

## 4. Updating an existing persona

Use the same slug and run make push-personas again.  The PR updates that
persona.  Keep updated_at current in meta.json; Collig uses the checksums in
index.json to tell users when an installed copy is out of date.

## Data contract

See scripts/validate_personas.py for the exact rules.  At minimum:

~~~json
{
  "slug": "ada-lovelace",
  "name": "Ada Lovelace",
  "display_name": "Ada Lovelace",
  "canonical_name": "Ada Lovelace",
  "description": "Mathematician and early computing pioneer.",
  "updated_at": "2026-01-01T00:00:00",
  "aliases": ["Augusta Ada King"],
  "sources": [{"title": "Example", "url": "https://example.com"}]
}
~~~

PERSONALITY.md must start with:

~~~markdown
# Ada Lovelace

... dossier ...
~~~
